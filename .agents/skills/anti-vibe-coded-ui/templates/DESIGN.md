## Overview

- **Visual thesis:** One sentence connected to this product and audience.
- **Surface mode:** Persuade / Operate / Read / Experience (or a justified mix).
- **Design priorities:** What should users notice, understand, and do first?
- **Distinctive signature:** One or two intentional details that give this product its own identity.

## Colors

Explain the role of each color and the surfaces on which it may appear. Validate contrast for actual text and controls; tokens marked `REPLACE` must not ship.

## Typography

Define display, body, UI, label, and data roles only where needed. Specify font fallback, scale, line height, letter spacing, and numeral treatment.

## Layout

Document container widths, grids, breakpoint behavior, spacing rhythm, page density, and responsive changes in hierarchy.

## Elevation and depth

Define when to use a divider, border, flat surface, or shadow. Use the least visual treatment that communicates the required hierarchy.

## Shapes

Document the radius and control-size scales, plus any project-specific geometry rules.

## Components

Record shared patterns and meaningful variants for navigation, buttons, forms, cards, tables, dialogs, notifications, and empty/error states as applicable.

## Do's and don'ts

List project-specific visual principles and anti-patterns. Explain the purpose behind each rule; avoid blanket bans that conflict with real user or product needs.
